# 头尾判定算法改进清单（2026-09-13）

约束前提：**无法获取产品图片（无独立真值来源）**、需**兼容更多产品**、希望**在线自适应**、**样本要少**。

---

## 约束之间的真实冲突

| 要求 | 可行形式 | 不可行形式 |
|---|---|---|
| 无图片 / 无真值 | 分布标定（自适应死区） | 权重学习、正确率估计 |
| 兼容更多产品 | 几何特征 + 产品档案 + 自适应量级 | 一个万能算法适配所有产品 |
| 在线 | **在线标定**（学"产品长什么样"） | **在线训练**（学"哪个特征更对"——需真值） |
| 样本少 | 分位数类稳健统计（20~30 帧） | 概率类统计（60~200 帧） |

**核心结论**：`无真值 + 在线训练` 不存在可行形式 —— 没有反馈信号的更新不是训练而是漂移。
但 `无真值 + 在线标定` 成立，因为标定只学**分布**（特征值通常多大），不学**对错**。

---

## 改进项（按投入产出比排序）

### P0-1 自适应死区：解决"兼容更多产品"的主要障碍

**现状**：`HeadTailFeatureDeadband = 0.10` 是**全局固定值**（`AlgorithmSettings.cs:128`）。
不同产品的不对称程度差异极大 —— 有的特征值天生 0.5，有的天生 0.05。
同一个 0.10 对前者形同虚设（总出死区），对后者全部落死区（永不裁决）。

**改法**：

```
deadband_i = k × median(|v_i|)      // k 取 0.3~0.5，按产品可调
```

- 用滑动窗口（30 帧）维护每个特征的 `|v|` 中位数
- 中位数是**稳健统计量**，不受异常帧影响
- **不需要真值** —— 它依据的是"这个产品的特征值通常有多大"，纯分布信息

**样本需求**：20~30 帧（分位数估计比概率估计稳定得多）

**为什么这条排第一**：
- 同时命中"兼容更多产品"和"样本少"两个约束
- 是当前**最大**的泛化障碍（固定死区把跨产品适配变成了手工调参）
- 改动小：只改 `BuildFeatures` 里死区的来源（`HeadTailFeaturePool.cs:487` 的 `deadband` 参数），
  调用点 `DetectionRecordService.cs:505`

**注意**：几何特征（①②③）与光度特征（④⑤⑥⑦）的 `|v|` 量级差异大，**应分别标定**。

---

### P0-2 三个自洽性指标：无真值场景下唯一可靠的反馈信号

**现状**：`HeadTailFeatureAudit` 已实现出死区率 / 裁决占比 / QR 一致率。
但**一致率需要真值**，无码场景不可用。需补三个**不需真值**的指标：

| 指标 | 定义 | 异常含义 | 驱动什么 |
|---|---|---|---|
| **特征分歧度** | 同帧出死区特征的符号种类数 | >1 = 特征互相矛盾 | 分歧高 → **加大死区**（让弱信号闭嘴） |
| **时序抖动率** | 连续帧方向翻转频率 | 高 = 判决不稳定 | 抖动高 → **加时序滤波** |
| **头向-位置相关性** | 判决方向 vs 产品画面位置的相关 | ≠0 = 被成像链污染（渐晕） | 相关 ≠0 → **修成像或弃用该特征** |

**灯箱条件让第三个指标的解读变清晰**：光照已固定，非零就一定是**固定模式**（镜头渐晕、
传感器响应不均）造成的，而不是光照变化 —— 这几乎成了纯粹的"成像链体检"。

**价值**：这是**唯一能驱动"无真值在线标定"的闭环** —— 不是学对错，而是学"怎么让系统自己稳定"。

---

### P1-1 级联顺序改为配置驱动 + 数据修正

**现状**：7 个特征的级联顺序**硬编码**在 `BuildFeatures` 的 `Add(...)` 调用顺序里
（`HeadTailFeaturePool.cs:500-568`），按"依赖前提数"人工排列（几何 → 亮度 → 结构 → 纹理）。

**这是缺陷 1：优先级是人写死的先验，不是数据事实。**

**改法**：
1. 顺序抽成配置（`AlgorithmSettings` 加一个特征顺序数组）
2. 拿到 `headtail_audit` 的 `AgreeRate` 排序后，**用数据修正先验**

```
现在（人工排）：①②③④⑤⑥⑦
数据修正后    ：①④⑤②⑥③⑦      ← 把可靠特征提前
```

**样本需求**：每特征 10~20 条即可判断**相对排序**（比估计绝对数值省得多）

**为什么值得做**：级联的主要错误来自"前面不可靠的特征压制了后面可靠的" ——
**把可靠特征排前面，这个错误就消失了。不需要融合，只需要正确的顺序。**

**与弱信号让位互补**：
- 顺序修正修"排序错了"
- 让位机制修"排序对了但先到者信号弱"

两者一起，级联的两个主要缺陷都补上了，且都不需要融合、不需要几百帧。

---

### P1-2 时序一致性滤波：利用"产品连续过料"

**思路**：单帧噪声是随机的，但**产品的物理朝向是连续的**。

```
最近 10 帧判决方向
  ├─ 9 同向 1 异向  →  异向那帧大概率错了（抖动/误判）
  └─ 5:5 交错       →  要么乱序摆放，要么系统在瞎猜
```

**更强形式（前后夹逼）**：若第 N−1 与 N+1 帧都判 +，而第 N 帧判 −，
则第 N 帧**大概率错了**（物理上产品不会单独一帧翻面）。

**样本需求**：0（纯时序滤波）
**零风险**：不动特征层，只在输出层做平滑

⚠️ **前提**：需先确认产线是**同向摆放**还是**混向**。
- 同向 → 极有效，强烈建议
- 混向 → 时序信息无用，只能靠单帧

### P2-1 产品档案：把"兼容更多产品"做成档案而非算法泛化

**思路**：与其让一个算法适配所有产品，不如**给每个产品建档**。

```
产品档案（首次上线自动建立，无需人工）
  ├─ 特征分布基线（前 30 帧的 median / IQR）
  ├─ 自适应死区（由上述分布算出）
  ├─ 常用裁决特征（观察一段时间后固化）
  └─ 正常方向范围（头向-位置相关性的正常值）
```

**新产品上线流程**：跑 30 帧 → 自动建档 → 之后每帧与档案比对，**偏离 = 异常告警**。

**与项目已有方向的衔接**：项目记忆中"产品档案 OBB 签名匹配"待做 ——
**建议把 OBB 签名与在线标定结合**，档案既存形状签名也存特征分布。

**关键**：权重/死区**按产品分别维护**，不跨产品共享（跨产品污染是在线自适应的主要风险）。

---

### P2-2 主动学习：无监督筛帧，人工只标最难的

```
系统自动判决
    ↓
只挑「存疑帧」：
  · 特征分歧大（自洽性指标 P0-2）
  · 置信度低（所有出死区特征 conf 都接近 1.0）
  · 与前后帧不一致（时序抖动）
    ↓
人工只看这些（约占 5%）
    ↓
高信息量真值 → 用于校准
```

**二分类让标注成本极低** —— 人工只需看一眼"头在哪边"。
**标 200 帧可能只需几分钟**，比收集 3000 帧自动真值更实际。

## 改进后的架构

```
有码帧（99.9%，有 QR 真值）：
  ├─ 用 QR 真值统计各特征 AgreeRate
  ├─ 修正级联顺序（P1-1）
  └─ 自适应死区标定（P0-1）
  └─ ⚠️ 权重更新仅在此路径（有真值）

无码帧（特征池的主战场）：
  ├─ 用当前死区 + 级联顺序 + 让位机制裁决
  ├─ 自洽性指标产出置信度（P0-2）
  ├─ 时序滤波平滑输出（P1-2）
  └─ 【不更新权重】← 无真值，禁止自我确认
```

**严禁**：无码帧的裁决结果回灌去更新权重 —— 这是自我确认（self-confirmation），
会让系统越来越相信自己而不管对不对，极端情况锁死在一个方向。

---

## 明确不做的事

| 做法 | 为什么不做 |
|---|---|
| 无真值的权重在线更新 | 自我确认，必然漂移且不自报 |
| 聚类定头尾 | 二分类必然聚成功，但仍不知哪类对 |
| 自编码器 / 深度无监督 | 数据量不够，且无真值无法验证效果 |
| 贝叶斯融合 | 需估 `p_i`，无真值场景无解 |
| 用一致性投票直接改判决 | 特征相关（④⑤⑥⑦ 吃同一张灰度图）会一起错 |
| 为每个产品手工调参 | 直接违背"兼容更多产品" |

## 落地顺序

| 阶段 | 内容 | 样本需求 | 风险 |
|---|---|---|---|
| **第 1 步** | 自适应死区（P0-1） | 20~30 帧 | 低（只改阈值来源） |
| **第 2 步** | 三自洽性指标（P0-2），**只统计不干预** | 0 | 零（纯统计） |
| **第 3 步** | 看第 2 步结果：不稳 → 闭环标定；很稳 → 什么都不做 | —— | —— |
| **第 4 步** | 时序滤波（P1-2，需确认同向/混向） | 0 | 低 |
| **第 5 步** | 级联顺序配置化 + 数据修正（P1-1） | 100 帧 | 低 |
| **第 6 步** | 产品档案（P2-1）+ 主动学习（P2-2） | 按需 | 中 |

**注意顺序**：每步都比上一步贵，且前几步零样本或低样本。
**预判第 1 + 2 步就够了** —— 自适应死区解决泛化，自洽性指标给出无真值下的可见性。
