# 通信协议：VGT 打码报文与编码器联动

## 报文内容（每产品一条）

| 字段 | 类型 | 含义 |
|---|---|---|
| X | double | 产品世界坐标 X（mm，九点标定后）|
| Y | double | 产品世界坐标 Y（mm）|
| RZ | double | 旋转角。默认域 (-180,180]；未知哨兵 -9999 的产品整条不发送。2026-09-17 起**发送域可选**：机械手腕关节只能转 ±90 且产品 180° 对称时，可在设置→通讯协议里把角度域切到 (-90,90]（折叠 180°，落库值不变）。|
| Barcode | string | 条码（noread 表示未读到）|

发送方式：UDP，按接收方配置分 LL / VGT 两条链路；**每批报文附带该帧的编码器值**（FrameResult.EncoderValue）。

## 编码器联动（机器人外推）

1. PLC 每 200mm 发硬触发 + 同步 UDP 上报当前编码器值（4 字节 uint）
2. MainAPP 收图后绑定该编码器值（严格同帧）
3. 机器人收到报文后：用**报文内编码器值**与**机器人实时编码器值**做差，乘输送线系数，外推产品当前实际位置后打码

⇒ XY 是"编码器值为 E 时刻"的位置快照；外推精度依赖报文编码器与图像严格同帧（当前由 PLC 触发随包发保证）。

## 已知保护逻辑

- 角度 -9999（未知）→ 整条不发，防错误旋转
- 编码器绑定延迟 >1s → Warning（断流恢复/UDP 丢包指纹）
- 相机丢帧（IsFrameLoss）/处理过载跳帧（NeedDrop）→ 发空报文告知"此帧无产品"
